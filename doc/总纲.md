## 一、项目是什么

Weft 是一门**独立的 RISC-V blocked/VLA kernel DSL 与编译器**，地位类似
Triton 对 GPU。

用户可以直接用 Weft Python eDSL 写一个 physical blocked kernel；Intent DSL、
其他编译器或代码生成器也可以把更高层算法 lowering 成 canonical Weft Kernel
MLIR，再交给同一个 Weft compiler。

Weft source 显式表达 task/grid、blocked region、pointer/index、logical mask、
load/store、block tensor-flow、reduce/dot、循环和状态；但不绑定固定 VLEN、
hardware lane、LMUL、vector register、RVV/IME 指令或寄存器分配。

Weft compiler 的目标是为一个 RISC-V target profile 选择 Scalar、RVV、IME
及未来扩展的 execution layout、owner 与低层实现，并发射可读
source、object 和 header。当前新主干已实现 RVV C++ source/object，以及第一条
IME selected-execution/source 路径；IME object、public header/runtime launch 仍未落地。
Weft core 不解析 Intent IR；Intent→Weft 属于上游 target plugin 或独立 bridge。
bridge 把逻辑算法变成参数化的 blocked program；Weft 只在该程序允许的空间内
选择 meta-parameter 和物理执行，不根据 kernel 名重新猜算法。

## 二、研究问题

> 一门类似 Triton blocked program、但适配 RISC-V VLEN-agnostic SIMD 与可插拔
> 矩阵扩展的 kernel DSL，能否在不暴露固定 lane/LMUL/register/instruction 的
> 前提下，把同一个 blocked kernel 合法、高质量地映射到 Scalar、RVV、IME
> 组成的 target domain？

## 三、两条不可动摇的本质

一切具体设计（结构消费契约、owner 选择规则、Physical Plan 推导公式、
真实 repro 纪律）都要向这两条负责，不为了别的目标牺牲它们：

1. **可扩展性（Extensibility）**——新增结构化原语组合、新增 RISC-V 扩展
   （新 owner）、新增硬件能力事实，主要局部增量接入；不要求为每种
   算子×格式×硬件组合手写一份完整实现。
2. **在可扩展性之上的高性能（Performance on top of extensibility）**——
   声明式/可组合的设计不能把专家级硬件知识压扁成最小公分母。每个 owner
   仍必须能表达自己最专的招数（RVV 的 `vfmsac`/`vrgather`/LMUL 折叠，IME 的
   矩阵类指令，等）。

## 四、系统边界（什么不做）

- 不做 GPU；GPU kernel 由 Triton/TileLang/cuTile 等系统负责。
- 不做通用图级/端到端模型编译；输入边界是一个 Weft kernel。
- 不解析 Python framework graph，也不读取 Intent AST/IR。
- Weft source 可以显式 blocked task/grid、tile meta-parameter、地址/index 和 mask；
  但不暴露固定 hardware lane、VLEN、LMUL、register allocation 或 instruction。
- tuning 只能在结构合法的 meta-parameter、execution layout 与 owner 候选中选择；
  不能改变 Weft source algorithm，也不能让非法候选通过测量变合法。
- 跨 owner 的共同层只表达 block tensor、execution region 和 value handoff；
  RVV 的 VL/mask/tail 与 IME 的 tile/accumulator 留给 owner-local 专化。

## 五、总体数据流

```text
手写 Weft Python kernel ─┐
                         ├→ canonical Weft Kernel MLIR（算法唯一真理）
Intent/其他前端 bridge ──┘
  → RISC-V analysis + capability（模块 B）
  → selected RISC-V execution/layout MLIR（模块 C/D/E）
  → 瞬态 Scalar/RVV/IME owner lowering（模块 F）
  → RISC-V source/object/header artifact（模块 G）
  → 一条真实 Weft→RISC-V 运行与数值对照 repro（模块 H）
```

各模块的目标、输入输出契约、关键未决问题见 `doc/modules/`。
面向 intentdsl 当前真实接口的重构判决、三层表示与 RISC-V execution-region
抽象见 `doc/weft-intent-riscv-rearchitecture.md`。

## 六、当前状态

本文档与整个 `doc/` 目录同时记录目标态与已落地边界；未完成的能力不会由已有
rank-1 repro 外推。截至当前：

- 已创建 standalone `weft_kernel` dialect 与 Python AST eDSL。canonical IR 覆盖
  typed pointer、task、constexpr、rank-N logical block、逐轴 singleton broadcast、
  `splat/full_like/zeros_like`、pointer/index、mask、load/store、pointwise、reduce、
  显式轴 contraction 和 carried loop；`W.dot` 是 rank-1/rank-2 contraction 的 source
  convenience，不是 target op。dynamic block extent 由 canonical SSA provenance
  证明相等，不会把两个无关的 `-1` 当成同一个运行时 extent。
- 已创建独立的 `weft_layout`、`weft_execution`，以及 sibling owner-local
  `weft_rvv_execution`/`weft_ime_execution` dialect。RVV selector 从 SSA 结构、layout
  与寄存器预算选择 lane ratio/LMUL；IME selector 从 canonical widening contract、
  logical extent、mask/pointer SSA 与 target capability 选择 fragment。两者都不按
  kernel/算子名匹配整段模板。
- 新 `weft-compile` 只接受 canonical Kernel MLIR，在同一进程完成 selection，并可
  用 `--emit=source` 按 selected owner 发射源码，或在 RVV owner 下继续生成真实
  RISC-V relocatable object。两条 `weft-rvv-selected-execution-*` library route 仍可
  分别使用。本轮由该 compiler 生成
  源码，再用临时 target harness 在真实 RVV 机器运行 RMSNorm
  （`rows=3, cols=513`），与标量参考对照得到 `max_abs=0, max_rel=0`。
- rank-2 row-major elementwise 已经通过同一主链：selected layout 明确为
  `order=[1,0], vector_axes=[1]`，emitter 生成外层 serial row loop 与内层 VLA RVV
  column strip；真实 RVV 上以 `rows=5, cols=513, stride=520` 得到 `max_abs=0`。
- 同一 rank-2 layout 已支持沿 vector axis 的 f32 sum projection：每个 serial row 在
  VLA strip 间累计 reduction，再以 rank-1 serial pointer/mask/store 写回。真实 RVV
  上运行两个 task、每个 `5×513`，得到 `max_abs=0`。
- canonical full rank-1 f32 contraction 已由 `W.dot` 进入同一主链；selected plan 保存
  `weft_rvv_execution.contract_config`，emitter 生成跨 VLA strip 的
  `vfmul + vfredusum/vfredosum` 与普通标量写回。真实 RVV 上以三个 task、每个
  `count=1027` 运行，得到 `max_abs=0`。
- 单 scope rank-2 f32 `lhs[M,K] × rhs[K,N]` 已使用 value-local layout component
  形成三个角色 group：lhs 是 serial projection，rhs/result 沿 N 轴 VLA vectorize；
  `contract_config` 只引用这三个 group，不复制 M/N/K 或 contraction axes。发射器生成
  `M serial → N VLA strip → K sequential` outer-product。真实 RVV 上以
  `tasks=2, M=5, N=37, K=29` 对照标量参考得到 `max_abs=0, max_rel=0`。
- `examples/repro_gemm.py` 的 `splat → for(block carried) → contract → yield → store`
  已进入同一主链。selected plan 用两个 `layout_conversion` use-edge 表示
  For-init/body-result 与 Yield/outer-result 之间的 layout-preserving handoff；emitter
  保留 canonical `range(0,K,BK)`，在每个 K0 迭代实现一个 BK contraction。真实 RVV
  上以 `BM=BN=BK=32, tasks=2×3, M=37, N=70, K=45` 运行得到
  `max_abs=0, max_rel=0`。
- constexpr 物理选择已从隐藏的统一常数改为 canonical 参数级 binding：
  `--meta BM=8 --meta BN=32 --meta BK=16` 在 selected plan 中按参数索引分别物化，
  生成的外层 M 块、N strip 上界和 K 步长分别为 `8/32/16`。真实 RVV 上以
  `tasks=3×3, M=19, N=70, K=45` 覆盖三个方向的尾部，得到
  `max_abs=0, max_rel=0`。旧 `--block-elements=N` 只保留为显式统一绑定简写，
  不再有默认 `256`。
- 普通逐-use layout conversion 已有第一条非 carried 实现：
  `examples/repro_dual_axis_sum.py` 的同一 rank-2 canonical splat 同时服务 axis 1 与
  axis 0 reduction。native group 选择 `order=[1,0], vector_axes=[1]`，第二个 use
  通过 `layout_conversion` 进入 incoming-only
  `order=[0,1], vector_axes=[0]` group；RVV emitter 从同一 scalar 重建 splat，而不
  假装完成寄存器 transpose。真实 RVV 上以 `tasks=2, rows=19, cols=70, value=1.25`
  得到 `max_abs=0`。
- `examples/repro_dual_axis_load_sum.py` 把同一个 canonical masked load 同时交给 axis 1
  与 axis 0 reduction。第二个 use 的 incoming-only group 不复制算法或 address map；
  selector 从 canonical producer closure 重新证明 axis-0 affine stride，emitter 在目标
  group 内重新发出 `vlse32`。selected IR 已 round-trip，source/object 已生成；这是一条
  store-free load rematerialization，不是寄存器 transpose，也尚无新增真机数值证据。
- layout 不再固定选择逻辑最后一轴。`examples/repro_columnwise_sum.py` 由
  `reduce(axis=0)` 驱动单组选择 `order=[0,1], vector_axes=[0]`；pointer affine
  分析从 canonical `row * stride + col` 推出 runtime lane stride，RVV emitter 发出
  masked `vlse32`。真实 RVV 上以 `tasks=2, rows=19, cols=70, stride=77` 得到
  `max_abs=0`。当前只开放非负 affine strided load，vector store 仍需 unit stride。
- whole scope 不再必须匹配“一个 rank-2 contract 恰好协调三组”的拓扑。
  `examples/repro_mixed_axis_sums.py` 在同一 kernel 中放置两个独立 reduction component；
  一个逐行沿 axis 1 归约，另一个逐列沿 axis 0 归约。selected plan 自然得到两个
  value-local group 与各自的 reduction config，source/object 已生成并可 round-trip；
  共享 RVV 主机预检时已有硬件探测负载，因此本轮没有新增其真机数值结论。
- reduction source 已从 `W.sum` 扩成统一的
  `W.reduce(value, init, axis, kind="sum|max|min")`，并保留 `W.sum/W.max/W.min` sugar。
  `examples/repro_rowwise_max.py` 生成 canonical max reduction、selected tree strategy 和
  真实 `vfredmax`。`examples/repro_softmax.py` 不是 fused 名称 op：它由 max、exp+sum、
  exp+normalize/store 三个显式 canonical loop 构成。每个 vector exp 由独立
  `weft_rvv_execution.unary_config(strategy="exp_poly_v1")` 选择，内部 working set进入
  寄存器预算；selected round-trip/source/object 已闭合。
- pointwise/memory layout 已从严格 rank-2 推广到 rank-N 的逐轴角色：一个 axis 进入
  VLA lane domain，其余 axis 按 `order` 嵌套 serial。`examples/repro_rank3_affine.py`
  的 canonical address graph 使 axis 1 成为唯一 unit-stride store axis，selector 因而
  选择 `order=[1,2,0], vector_axes=[1]` 并机械发出 axis0→axis2→axis1-VLA；没有
  rank3_affine 名称分支，selected round-trip/source/object 均已闭合。
- canonical integer signedness 与唯一 widening contraction 已进入同一 Kernel IR：
  `examples/repro_ime_contract.py` 表达 signed `si8[BM,BK] × si8[BN,BK] →
  si32[BM,BN]`，不含 IME op 或 instruction。显式 `vlen-bits=256` 和精确
  `xsmtvdotii` extension token 选择后，每个独立 contract site 生成三个 serial shared
  layout group，并由自己的 `weft_ime_execution.contract_config` 共同拥有；record 只保存
  物理 `4×4×8` fragment、VLEN 与 `fragment_tiled` strategy，不复制逻辑 M/N/K、dtype、
  axes、mask、pointer 公式或 `vmadot` 拼写。selector 已不再要求整个 kernel 恰好是
  两个 load/一个 contract/一个 store：多个互不重叠的 contract site 独立选择，任意
  已解析的正整数逻辑 M/N/K 由 emitter 分成 `ceil(M/4)×ceil(N/4)×ceil(K/8)`。
  这里的“任意”仍限于 flat、direct-load/direct-store、zero-fill/zero-init 的 signed
  widening contract envelope，不代表嵌套控制流、混合 owner 或 rank-N IME 已完成。
  emitter 按 canonical 坐标/指针/mask 做 tail-safe K-fragment scratch packing，以真实
  `vmadot` asm leaf 在寄存器中累加完整 K-loop，再 masked `4×4` scatter。逻辑
  `8×12×16`、非整除 `5×6×9` 以及双 contract selected/source 均已通过 round-trip 或
  RISC-V clang syntax check；本机没有
  SpacemiT toolchain/IME target，因此当前不宣称新主干 object、真机数值或性能证据。
- canonical rank-N pointwise/memory 已有一个可执行布局切片，但 reduction/contract
  物理实现仍限 rank-1/rank-2。selected IR 已加入按 canonical operand use 记录的
  `layout_conversion`；目前真实实现 layout-preserving carried handoff、可证明的
  splat-per-use rematerialization，以及无 intervening store 的 masked-load
  rematerialization。寄存器重排和通用跨 owner use-edge 仍未发射。多 vector axis、
  strided store/indexed gather、rank>2/沿物理 serial axis/多轴 reduction、
  reshape/transpose、一般
  rank-2/rank-N contraction、多个 carried state、多阶段 GEMM、自动 BM/BN/BK
  tuning、更多 IME primitive/layout、跨 owner cleanup 与 IME object/runtime、Scalar owner、
  header/runtime launch 和完整 tuning 尚未完成。
- 旧 bounded problem、whole-kernel variant、format body 和 route graph 仍有代码资产
  并仍可由工具注册，但两条新 selected-execution route 已经绕开它们；待新 DSL 覆盖
  关键算子结构后应及时删除，不能恢复为新主干权威。
